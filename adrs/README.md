# ADRs — Architecture Decision Records

## Overview
This directory holds the accepted Architecture Decision Records for the framework and the reference platform it describes. Each ADR captures a single significant decision, its context, options, and consequences.

## Purpose
To preserve traceable rationale so future engineers understand why the framework is shaped the way it is.

## Responsibilities
- Preserve an immutable, chronological log of significant decisions.
- Record status transitions from proposed through accepted to superseded.

## Contents
- Numbered, accepted ADR documents (for example 0001-record-architecture-decisions.md).
- Superseded ADRs, kept for history and clearly marked as superseded.

## Out of Scope
- [Blank ADR forms — the template lives in the ADR template directory.](../templates/adr/)
- Draft or rejected proposals still under discussion.
- Application code, diagram sources, or specifications.

## Relationships
- [ADR template](../templates/adr/) — the blank form new ADRs start from.
- [Architecture Decisions](../bootstrap/ARCHITECTURE_DECISIONS.md) — the Foundation decisions a future ADR may supersede.

## References
- [Master Plan](../bootstrap/MASTER_PLAN.md) — the constitution governing the framework
- [Architecture Decisions](../bootstrap/ARCHITECTURE_DECISIONS.md) — the ratified Foundation decision record

## Conventions
- ADRs are numbered sequentially and never renumbered; once accepted, an ADR is not edited except to change status and link to its successor.
