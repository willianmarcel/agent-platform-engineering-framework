# Example — Architecture Requirements Specification (conceptual)

A conceptual, technology-neutral example illustrating **methodology only** for the Architecture Requirements
library. It shows the *shape* of a compliant Architecture Requirements specification; it defines no real
product and names no technology.

- **Intent:** *(illustrative)* Specify what the architecture must satisfy: drivers, constraints, quality-attribute scenarios, risks, trade-offs, and the forces behind decisions.
- **Content:** an illustrative Architecture Drivers with its Architecture Constraints stated conceptually.
- **Acceptance Criteria:** each criterion measurable in the real specification.
- **Traceability:** derives from the domains library;
  constrains the runtime library.
- **Owner:** Platform Architect; owning chapter [Chapter 06](../../../handbook/06-reference-architecture/CHAPTER.md).

This example illustrates the methodology of a Architecture Requirements specification, not a real product.
