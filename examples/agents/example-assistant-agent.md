# Example — Illustrative Assistant Agent (conceptual)

A conceptual, **non-executable**, **technology-neutral** example demonstrating APEF concepts. It
defines no real product and names no vendor, product, framework, SDK, or implementation detail;
it illustrates methodology only.

**Intent.** Assist an operator by handling a defined class of judgment-heavy requests to an agreed standard, with human oversight retained. *(illustrative)*

**Job served.** The operator's job of handling a high volume of judgment-heavy requests consistently — a product concern owned by [Chapter 02](../../handbook/02-product-thinking/CHAPTER.md).

**Capabilities used.** References the product capabilities the platform provides; the agent composes them rather than defining new ones.

**Intelligence required.** An abstract *language understanding and generation capability*, requested **by capability** behind the provider abstraction ([Chapter 09](../../handbook/09-provider-platform/CHAPTER.md)) — no provider is named.

**Runtime lifecycle.** Admitted → active → completed, managed by the runtime ([Chapter 07](../../handbook/07-runtime-platform/CHAPTER.md)); the agent is executed, not self-executing.

**Governance.** Subject to control-plane policy and quotas ([Chapter 11](../../handbook/11-control-plane/CHAPTER.md)).

**Acceptance criteria.** Requests are handled to the defined standard, oversight is retained, and the target consistency is met — each criterion measurable in a real Agent Specification.

## Concepts demonstrated

This example demonstrates agent intent and lifecycle (07), agent assembly (08), the job/outcome it serves (02), provider abstraction (09), governance (11).
