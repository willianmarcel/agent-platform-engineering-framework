# Release Process

## Purpose
The Release Process defines how versions of the framework are cut, reviewed, and
published, and how changes are communicated. Because APEF is a documentation and
engineering framework, a "release" is a versioned, coherent state of its guidance.

## Contents
- The versioning scheme (Semantic Versioning) and what constitutes a breaking change
  to framework guidance.
- The steps to prepare a release: freezing scope, updating [`../CHANGELOG.md`](../CHANGELOG.md),
  and running the release review.
- Approval and tagging procedure, and how released versions are published under
  [`../docs/`](../docs/).

## Relationships
It consumes the outputs of [`QUALITY_GATES.md`](QUALITY_GATES.md), follows the phasing
in [`ROADMAP.md`](ROADMAP.md), and pairs with the release
[`../playbooks/release-review/`](../playbooks/release-review/).

## Current state
Purpose-defined during Foundation. The full release procedure is authored before the
first framework release in a later phase.
