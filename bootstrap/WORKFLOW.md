# Workflow

## Purpose
The Workflow document describes the day-to-day process for contributing to APEF: how an
idea moves from proposal to specification to accepted, reviewed artifact.

## Contents
- The end-to-end contribution flow (propose → specify/ADR → draft → review → merge).
- When and how to write an ADR (using [`../templates/adr/`](../templates/adr/)) and where
  accepted ADRs land ([`../adrs/`](../adrs/)).
- Branching, commit-grouping, and pull-request expectations.
- Where each quality gate from [`QUALITY_GATES.md`](QUALITY_GATES.md) is applied in the flow.

## Relationships
It is the operational counterpart to [`ENGINEERING_GUIDE.md`](ENGINEERING_GUIDE.md) and
[`REPOSITORY_GUIDE.md`](REPOSITORY_GUIDE.md), and it feeds the
[`RELEASE_PROCESS.md`](RELEASE_PROCESS.md). It aligns with [`../CONTRIBUTING.md`](../CONTRIBUTING.md)
at the repository root.

## Current state
Purpose-defined during Foundation. The detailed workflow is authored in the Engineering
phase.
